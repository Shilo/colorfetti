# Fresh primary-source API and algorithm research

Consulted independently online October 18, 2026; not copied from Claude's API log. Sources below were opened as current primary documentation. These are applicability decisions, not measured speedup claims.

| Primary source | Current guidance relevant here | Actual callsites, decision, fallback and required experiment |
|---|---|---|
| [HTML timers and microtasks](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers) | Nested timer delay is clamped after five; many microtasks can prevent rendering, and a microtask does not yield to the event loop | `quantize.yieldTask`, all core pause/band helpers: keep real posted task. setTimeout0 remains capability fallback. Replacing with resolved Promise would break responsiveness semantics. Browser rAF/input gap and elapsed tests required for any scheduler change |
| [HTML MessagePort task queues and garbage collection](https://html.spec.whatwg.org/multipage/web-messaging.html#ports-and-garbage-collection) | Ports own task sources; discarded unclosed ports can raise transient memory until coordinated garbage collection | `yieldTask` closes both ports in delivery callback, so no observed missing-close defect. Persistent shared channel could reduce creation but introduces queue and teardown concerns; measure channel/GC share in actual workflows before adding global scheduler |
| [Prioritized Task Scheduling draft](https://wicg.github.io/scheduling-apis/#dom-scheduler-yield) and [API support reference](https://developer.mozilla.org/en-US/docs/Web/API/Scheduler/yield) | Yield continues via prioritized task; continuation priority can differ from ordinary newly enqueued tasks. Support reference still labels availability limited | Optional feature detection possible in `yieldTask`, keeping channel/timer fallback. Must test multiple tile/count/export fairness, cancellation, main+worker context and supported engines; scheduler throughput alone no acceptance. Current implementation broadly portable |
| [HTML transferable objects](https://html.spec.whatwg.org/multipage/structured-data.html#transferable-objects) | Transfer serializes ownership; backing resource becomes unavailable in sender. Transfer list must reference transferred resource that receiver can access | `palette-limit-client.runWorker` and generated client create `.slice()` chunks then transfer new buffers; `summaryHistogram` creates disposable RGBA/weights instead of transferring immutable originals. Preserve source bytes. Compare whole-workflow CPU and copied bytes for histogram optimization, not postMessage latency alone |
| [ECMAScript TypedArray.slice](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-%typedarray%.prototype.slice) / [subarray](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-%typedarray%.prototype.subarray) | Slice makes elements in a new typed array; subarray views existing backing storage | Core cooperative chunk readers use subarray without copy; worker send uses slice before transfer intentionally. Swapping APIs blindly would detach original frame buffers. Histogram transfer saves repeated full-source slices where completed safe metadata exists; measure cold/hot/fallback separately |
| [ECMAScript safe integers](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer) | Number integers above2^53-1 are not all uniquely represented | `summaryHistogram` requires safe positive integer delays and final total; partial alpha fallback avoids count-by-cut ambiguity. `createGeneratedAccumulator` global mass/moments use checked safeAdd. Test boundary and fallback; don't infer arbitrary weights are safe because Float64 stores them |
| [Original Oklab publication and matrices](https://bottosson.github.io/posts/oklab/) | Forward transform uses linear sRGB, cube roots and published matrices; matrices updated Jan25 2021 | quantize, limiter, generated and Cleanup use matching published forward constants with intentional differing precision in written trailing zeros. RGB metric is encoded-channel distance by app contract. Avoid changing constants, fast cube-root approximation, alpha weighting or tie order under performance scope. Fresh nearest/scalar and differential full output probes must accompany kernel change |
| [Long Tasks API](https://www.w3.org/TR/longtasks-1/) | Long Tasks expose blocking tasks>=50ms and limited attribution, not all CPU or smaller frame stalls | Banded reanalysis/quantize/cleanup8ms targets do not guarantee frame budget or task ceiling. Record rAF gaps/input readiness plus elapsed and CPU, and worker attribution separately; zero Long Tasks is not no work. Node kernel timing cannot satisfy browser/device gate |
| [ECMAScript Set.has](https://tc39.es/ecma262/multipage/keyed-collections.html#sec-set.prototype.has) / [Array.includes](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.includes) | Both compare these finite integer RGB keys with equivalent membership semantics; no order iteration is needed for a membership query | `palette-generated.finish` seed loop currently calls colors.includes for each candidate. Research-only Set candidate keeps ordered colors array and adds at most64 numeric keys, replacing only membership. Exact generated palettes/diagnostics required, including duplicate binned RGB representatives; whole job and native worker/UI benefit must justify added state. API semantics do not establish speed |

No worker/OffscreenCanvas/SharedArrayBuffer/Wasm rewrite is recommended from general documentation. Pixel exactness, browser support, captured immutable ownership and practical measured costs govern suitability.
