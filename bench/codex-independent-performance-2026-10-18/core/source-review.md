## Independently ranked opportunities and experiments

1. **Cold full-source Icon/Stencil preparation**: source review proves full resolution allocation/flood even sampled wall and cache loss on source/cut change. Fresh native/browser timings must establish current stalls. Cooperative preparation/worker could improve responsiveness without topology change, but high integration/cancellation/memory risk; no patch authorized or justified by source reading alone.
2. **Exact Palette count and exact render duplication with dither/Cleanup**: instrumentation should compare captured full-source signatures and completed `used` witnesses before sharing work. No full-frame retained cache; merely suppressing captions violates contract. App may already satisfy same-surface exact metadata before count starts, so source possibility is not a proven bottleneck.
3. **Original summary overflow scan**: >4096 color source first partially scans for bounded summary, then exact2MiB counter scans source. Focused profile across 4096/4097 and realistic high entropy; avoid retaining a 2MiB cache or moving full RGB count into every summary scan unless practical benefit beats low-color regressions.
4. **Generated seed O(U*64²) and repeated membership scan**: `colors.includes` in farthest-point seed adds at most64 comparisons inside U*64 loop. A fixed selected representative bitset could preserve output; browser profile first, and binned duplicate representative RGB needs exact matching membership. No implementation because fit core may run worker and transport/UI costs dominate.
5. **Repeated fresh palette preparation and summary scratch allocation**: tiny control operations allocate vectors, normalization and32KiB histogram temporary even warm/ineligible cases. Typical P<=64 and rare cap updates likely make allocation small; quantify before adding more caches or retained palettes.
6. **Scheduler API / channel reuse**: one MessageChannel per yield gives actual task semantics, closes ports correctly. `scheduler.yield` feature path might lower overhead but continuation priority can affect queue fairness, and support fallback required. Synthetic scheduler throughput alone would be insufficient user-facing evidence.
