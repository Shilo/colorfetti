# Fresh primary API research — October 18, 2026

These sources were consulted during this Codex evaluation. Application-specific conclusions are inferences from current call sites, to be tested; documentation is not a performance result.

| Primary source | Actual call sites and applicability | Decision / tradeoffs / required evidence |
|---|---|---|
| [W3C WebCodecs current draft](https://www.w3.org/TR/webcodecs/) (October7,2026), sections9.4,10.2,10.3 | `image-decode.js`: PNG `ImageDecoder.isTypeSupported`, stream constructor with default color management, `VideoFrame.copyTo`, frame/decoder close. Spec allows codec support to vary; explicit copy format can require RGB conversion. Packed native sRGB metadata matches spec's bt709/iec61966-2-1/rgb/fullRange definition. | Preserve capability/error fallback and transform checks. Close explicitly releases codec resources and aborts work; frame close remains separate. Direct native copy avoids needless conversion only when proven same managed space. Native profile/alpha fixtures plus forced unsupported/transform/abort tests needed. Do not assume Safari support or compare readback noise with pixel truth. |
| [WHATWG HTML canvas](https://html.spec.whatwg.org/multipage/canvas.html) | `image-decode.js` fallback uses bitmap→2D with explicit sRGB and `willReadFrequently`, then getImageData; bitmap and canvas size released in finally. Native decoders/color management affect resulting bytes. | Keep readback only as import fallback. `willReadFrequently` is a resource-usage hint, not a promised speedup. `bitmaprenderer` is useful for displaying an ImageBitmap, but import needs CPU RGBA, so substituting it does not remove required readback. Do not use canvas encoding for exact exports. |
| [WHATWG structured data / transfer](https://html.spec.whatwg.org/multipage/structured-data.html#transferable-objects) | All import/limiter/generated/cleanup/GIF worker postMessage transfer lists; fflate consume. Transferring ArrayBuffer detaches sender, and duplicate/invalid transferables fail. | Preserve originals: only unpublished import buffers or fresh128KiB slices/new byte-index outputs transfer. Duplicate-buffer import guard is necessary; fallback must decode File rather than read detached data. Check byteLength/source preservation and queue cancel/failure native flows. Transfer reduces copying but does not make total source/job allocations free. |
| [fflate author's README](https://github.com/101arrowz/fflate) and installed package source | `save.js` sync/async zlib level3, consume option, returned terminate callback; stored ZIP. Author documents worker initialization overhead for small inputs, immediate cancel without callback, and consume detaching input. | Documentation supports testing a small-input sync branch, not selecting a universal optimum. Require exact filtered-byte boundary65535/65536/65537 and tiny/largest-below/above adverse native AB/BA, including module-cold and warm. CRC/packing/assembly remain main-thread work. Existing B4 aggregate rejection and acceptance override require fresh measured challenge. |
| [WHATWG DOM AbortSignal](https://dom.spec.whatwg.org/#abortsignal) | Client subscriber controllers; `AbortSignal.any` for Lospec/dialog/download paths; abort listeners around codec/worker/stream requests | Synchronous abort listeners must release queued ownership immediately. Noncancelable File reads and module imports still need post-await stale checks. Independent export subscriber keeps shared request alive. Capability failures keep fallback, runtime failures follow explicit error policy. Test cancel queued/active/during download and independent subscriber survival. |
| [W3C Clipboard API](https://w3c.github.io/clipboard-apis/#clipboarditem) | `copyOne` constructs ClipboardItem with promised PNG and calls navigator.clipboard.write in initiating gesture; attaches catch to original preparation promise. | Preserve gesture ordering and report native transport separately from exact prepared PNG. Clipboard permission/user-activation and platform alpha rounding can differ by browser. A Save witness does not verify native Copy. Native available-API/actual write checks are needed; unavailable transport must remain an explicit gap. |

Compression Streams was considered via the [WICG primary specification](https://wicg.github.io/compression/), whose served page did not expose readable text to this browser tool. No implementation or support claim is made from that failed retrieval. A codec substitution would change compressed bytes, require new level/cancellation/support analysis, and lacks a demonstrated app bottleneck here; no candidate is justified from generic API availability.

Support evidence is capability-tested on actual owned Codex/Android pages and unit mocks, not inferred from draft exposure attributes. No Apple browser/device is available to this reviewer.
