# Fresh primary-source API evaluation

Consulted live October 18, 2026 for the independent current-baseline audit. These are applicability decisions from actual reviewed call sites. Documentation describes semantics and support, not an app speedup. Browser-specific measurements and unsupported surfaces are reported separately. No dependency or API migration was made.

| Primary documentation | Current app call sites and applicability | Support/fallback, tradeoff and falsifying experiment |
|---|---|---|
| [Svelte $effect](https://svelte.dev/docs/svelte/$effect) | `CanvasGrid` connects observers; `Pixels` uploads ImageData; `ImageViewer` handles modality, input and delayed refinement. Effects batch after DOM updates, track synchronous reads, and call returned cleanup before rerun/destroy. Asynchronous callback reads do not create dependencies. The stable CanvasGrid key is therefore meaningful; its scheduled measure sees latest props without making every frame an effect dependency. | Installed Svelte5.57.2, no alternate framework path. Keep resource teardown in effects. Trace actual effect runs after unrelated state before claiming broad reactivity cost. Replacing effects with synchronous derived writes would change lifecycle timing. |
| [Svelte $derived](https://svelte.dev/docs/svelte/$derived) | Viewer grid/sampling read scale but not pan; scalar `mw`/`mh` boundaries in Tile are coordinator-owned. Derived values use push/pull invalidation and skip downstream changes when recomputation yields the same value. A newly allocated object still differs by identity, so broad object props need caller scrutiny. | Existing Svelte runtime; no new support concern. Avoid adding memoization merely because expressions rerun: count downstream conversion/paint before optimizing. Validate panning does not resize/rerender source buffers. |
| [Svelte untrack](https://svelte.dev/docs/svelte/svelte#untrack) | Viewer initial comparison uses a deliberate local snapshot; refinement compares current target against inspectionScale without subscribing to the latter. PaletteImport initial request stays stable during acquisition. | Existing installed runtime API. Untrack is not a speed directive: suppressing real dependencies can leave stale UI. Exercise source switch, modal reopen, zoom settle and rapid replacement. |
| [Svelte $state.raw](https://svelte.dev/docs/svelte/$state#$state.raw) | PaletteImport colors/baseline/selected are replaced through map/filter/spread or whole-result assignment, making them eligible for a raw-state experiment. Raw state avoids deep proxy creation but requires reassignment for updates; it does not make DOM work disappear. | Existing Svelte5 API. Fresh full-app raw-array variant was independently built/tested in three auxiliary pairs: median paired renderer saving0.94ms, one pair slower, below the unchanged10ms/5% gate. Do not ship solely because the documentation mentions possible large-array savings. |
| [Chrome team layout guidance](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing) | CanvasGrid batches geometry reads before root writes. Tooltip.position writes maxWidth and then measures; a visible tooltip can require style/layout. Viewer DOM point gets dialog BCR per input. Editor has nested flex/grid + bounded64 swatches. | Ordinary APIs widely supported. Measure forced style/layout and total layout separately with trace attribution; avoiding one getBCR does not remove required presentation layout. Test same visual result, font readiness, resize and visual viewport changes. |
| [ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver) | CanvasGrid watches first art/surface/bar and schedules two rAFs, avoiding immediate mutation from its callback. Viewer and root geometry use measured dimensions. The documented delivery/loop considerations support avoiding writes that resize the observed target during delivery. | Widely available since2020. Existing app assumes support; no new fallback proposed. Count observer→schedule→measure ratios and same-value variable writes during real controls; test first tile replacement, empty wall and both viewport orientations before narrowing. |
| [MutationObserver observe](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver/observe) | CanvasGrid `{childList:true,subtree:true}` sees additions/removals throughout #app, including editor swatches, tooltips inside dialogs and conditional controls; attribute/pixel writes do not directly trigger it. Disconnect is explicit on teardown. | Widely available since2015. Narrowing scope can miss dynamically replaced first art; filtering only currently found art is unsafe across replacements. Instrument callback counts + root query/layout cost and verify checker placement after import/remove/demo transitions. |
| [CSSOM setProperty editor draft](https://drafts.csswg.org/cssom/#dom-cssstyledeclaration-setproperty) | CanvasGrid's three root custom-property assignments can repeat identical serialized values. The current draft conditions style-attribute updates on the declaration operation's update result, but permits implementation algorithm differences when serialization is unchanged. | Work-in-progress specification, not a browser timing guarantee. Identical assignment counts alone prove neither mandatory layout invalidation nor a useful gain from adding JavaScript guards. Observe actual style/layout/geometry CPU; preserve custom-property priority/serialization semantics. |
| [requestIdleCallback](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestIdleCallback) | Considered for noncritical caption/layout housekeeping. Automatic exact captions/Reuse and responsive checker placement need eventual useful readiness. Idle callbacks can wait a long time; a timeout can force queued work. | Limited availability; would need feature detection and current posted/timer fallback. Replacing existing fair serial posted queues can starve captions or move cost to worse windows. Reject generic idle migration without controlled final-readiness/input evidence. No idle rewrite proposed. |
| [OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas) | Considered for Pixels and paint-only palette canvases. OffscreenCanvas supports worker rendering and transfer, but workers still need correctly owned sampled data and UI remains DOM-bound. Tiny1²/100² paintings do not justify transport/setup by API reputation. | Core interface widely available since2023; specific contexts/features vary. Existing canvas2D path must remain fallback. Benchmark source conversion, transport and upload separately; preserve forced-dark color protection, cancellation and native export bytes. No worker-canvas rewrite proposed. |
| [Canvas width reset](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/width) | Pixels conditionally resizes, already respecting destructive resets. Palette painting actions always reset dimensions on update, including same dimensions; they intentionally clear empty overview and restore painting state. | Widely available since2015. Potential dimension/equality guard must preserve empty clearing, invalid-input atomicity and fresh context state. Count actual repeated action updates before a comparative variant; changing color-critical canvases to CSS/SVG is outside exactness contract. |
| [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) | animationVisibility uses one observer/Map and edge thresholds0/EPSILON; visible callback gates animation playback work. It cannot provide immediate synchronous exact pixels on every boundary. | Widely available; action explicitly treats unsupported/constructor failure as visible. Extending to stills requires visible readiness/scroll-in behavior proof; do not silently display stale art or alter drag quality budgets. Test edge crossing, hidden viewer ownership and last-consumer teardown. |
| [showPopover](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/showPopover) | Tooltip uses feature detection, manual top-layer popover, modal-local parent and fixed positioning fallback. Top-layer placement avoids clipping but still requires geometry for fitting. | Baseline2024, older browsers may lack it. Existing fallback retained. A shared/lazy tip optimization must keep dialog inertness/accessibility and hover-gap behavior; tests should include dialog close, dynamic text and tooltip-first Escape. No CSS-anchor migration inferred from newer API options. |
| [WAI tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) | Tooltip action provides role=tooltip, aria-describedby at mount, focus retention, Escape dismissal and pointer traversal. This directly constrains lazy-DOM ideas: retaining only a data attribute would lose accessible descriptions before first show. | WAI explicitly labels the pattern work in progress, not final consensus. App's richer touch behavior remains current contract. Attribute missing-description and hidden-DOM cost independently; require accessible relationship from initial mount and cleanup after destruction. |
| [Vitest exclude](https://vitest.dev/config/exclude), [CLI list](https://vitest.dev/guide/cli.html#list) | Vite test config spread configDefaults but excluded only root .tmp. The fresh files-only JSON list proved258 copied nested-worktree tests were included. Extending exclusions with `**/.claude/worktrees/**` safely targets known scratch ownership. | Current docs include Vitest5 details; installed4.1.11 CLI was actually executed, preserving installed versions. Config exclude replaces defaults unless spread; default discovery remains outside scratch. Exact66-path equality, ordinary future-directory discovery/execution and whole suite were verified. See test-discovery.md for setup EPERM and workspace TEMP workaround. |

Current API guidance supports selective attribution experiments. It does not establish a useful gain from pooling tiny gesture objects, removing tooltip accessibility, masking fewer visible frames, delaying committed state, removing blur or replacing the canvas/export architecture.

For the optional auxiliary harness, [Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox) documents that Chromium sandboxing is opt-in; the prepared launcher explicitly sets `chromiumSandbox: true` and uses the installed Edge channel. [CDPSession](https://playwright.dev/docs/api/class-cdpsession) documents the low-level metric transport. This auxiliary surface remains separately labelled and cannot satisfy actual Codex Browser or phone gates. No browser was launched while preparing the harness.
