# M5 palette-editor contrast verification

The baseline is commit `83ff77b163641f529ab8f615d3f633e23c59fce8` with unchanged `src/palette-import.css` SHA256 `B08EEE1AA7B766BF9784E470161A1F626B084245BA873AEF8FF95300AEDE0DBA`.

Four scoped declarations reuse existing semantic GlassKit/app roles: Save palette/Save changes use `--gl-color-primary-on-surface`, unselected import methods and the Cancel footer use `--fg`, and a local `--muted` mixes 75% foreground with 25% opaque surface for editor hints/metadata. Selected method heading colors, surface states, palette values/canvases, disabled opacity and native controls are preserved. Adversarial review of the initial two-role correction found Cancel and hints at 3.3358:1 in light theme, extending the correction to these related roles.

Before, initial and final revised production builds passed. Immutable in-memory local servers serve `.tmp/conversion-fixes-m5-before` on port 5206, `.tmp/conversion-fixes-m5-after` on port 5207 and final `.tmp/conversion-fixes-m5-revised` on port 5208. `serve.mjs` accepts the build directory and port. The scripts and text receipts are evidence; generated screenshots and build output are local artifacts. Other agents' unrelated source changes entered the final combined build; `source-build.json` records the CSS source and each build's index assets. The CSS under review is limited to `src/palette-import.css`.

Codex desktop Chromium browser checks covered populated and empty drafts, light/dark, 1280×720 and 390×844, actual hover on Save/Cancel and unselected methods, selected method keyboard focus, Save/Cancel keyboard focus, 65-color pagination metadata, and successful saving/re-opening an exact three-color draft. After the final revision all affected themes, widths, hover/focus and save/reopen were tested again. Save stayed disabled with 0 colors and used opacity .5. Method targets were 44px high; Save 52px. No horizontal document overflow occurred at the two widths.

`contrast-receipt.mjs` regenerates `contrast-results.json` from the raw computed-style captures. It composes translucent text and ancestor surfaces up to the opaque dialog backing and applies WCAG sRGB relative luminance. It retains 165 observations across all review rounds, including 109 final-revision observations and exempt disabled controls. All enabled final observations exceed 4.5:1; the worst, 5.4242:1, is light Save. Light baseline Save 2.259:1 and unselected methods 3.430:1 reproduce the master review. Dark Save improved 6.942→9.877 at rest, and unselected methods 5.123→10.970. Selected dark methods remain 5.643. Final hints are at least 5.923 light/8.592 dark and Cancel at least 12.375 light/10.970 dark across measured states.

Some captures intentionally retain transition intermediates; selected/hover semantics are recorded separately from computed colors. Pointer hover was verified with `:hover`, selected focus with `:focus-visible`. Right-click Save/Cancel inspected hover without submitting or dismissing the draft. Screenshots were saved from the supported CUA tab screenshot API and visually checked. `before-*.jpg` show the baseline, `after-*.jpg` the superseded initial correction, and `revised-*.jpg` the final result.

Limits: the exposed browser capabilities do not provide forced-colors or coarse-pointer emulation. Existing system-color adapters and UA forced color adjustment are unchanged. Responsive checks use a desktop browser, not a physical phone. This scoped fix does not claim every other muted label in the application meets contrast requirements.
