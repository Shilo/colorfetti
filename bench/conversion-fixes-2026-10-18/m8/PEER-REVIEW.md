# M8 independent adversarial review

The peer reviewer accepts the revised implementation within this scope. No remaining correctness issue was found in exact PNG state mapping, alpha preservation, byte packing, size selection or cancellation. Browser acceptance belongs to the coordinator's separate desktop receipts.

`peer-review.mjs` independently imports the frozen pre-M8 `8a84b6c` writer and compares **114 cases** with the current implementation. A Node inflate/CRC/chunk reader and Sharp both verify complete stored RGBA, including hidden RGB under alpha zero. Cases cover state thresholds 1/2/3/4/5/16/17/255/256/257, high target indices, offset typed-array views, 65,539-pixel-wide asynchronous packing, late malformed alpha/indices after overflow, black entries, all 256 opaque RGB colors plus another partial state, and exact legacy compaction-cap neighbors. Palette output never exceeds the complete original PNG baseline. Legacy output above the cap is byte-identical to the old writer except its explicit 13-byte sRGB chunk. `peer-review-results.json` records source hashes and individual results.

Four directly affected unit suites independently passed **85 tests** after the final revision. Their validation and cancellation checks include rejection before compression, actual second-worker termination and late-callback suppression. An initial concurrent run hit the existing clipboard subprocess test's five-second timeout during benchmark load; the sequential repeat passed. `peer-unit-tests.txt` records that final run. The bounded exact-state collector uses 132,354 bytes of typed lookup/table storage, retains no extra per-pixel index raster and stops adding states at overflow. Complete alpha validation happens before either compressor. Baseline raw rows are cleared before allocating a candidate; this is logical ownership, not a garbage-collection or process-memory guarantee.

The review found a real performance problem in the first implementation: optional double encoding raised an admitted 16 MP random legacy PNG from approximately 163 ms to 424 ms in one alternating-order run. `peer-cost-uncapped-results.json` preserves that rejected implementation's evidence. The agreed fix limits optional legacy compaction to **262,144 pixels** and fuses role validation with baseline packing. Independent exact 262,143/262,144/262,145-pixel tests and a real 513×512 case verify the boundary. Above it, there is one tagged 2-bit encoding and no role-count pass or candidate compression. Below it, a compact candidate replaces the tagged baseline only when its complete PNG is strictly smaller; the implementation's separate tests also cover real losing and tied candidates.

`peer-cost.mjs` repeats PNG-only cost checks at 512², 2048² and 4096² and proves large PNG byte identity apart from sRGB. On this Windows machine, capped 512² random output took roughly 4–8 ms in observed runs; large exports still have measurable validation overhead and remain synchronous. Raw alternating-order samples are retained in `peer-cost-results.json`; system load changed wall times considerably, and Windows process-CPU readings are coarse. These are diagnostic observations, not browser latency ceilings or a universal speedup. Full Palette Keep size selection remains asynchronous and can perform two compression passes. The code is accepted with these explicit tradeoffs; migrating legacy PNG Save/Copy to cooperative asynchronous work remains separate follow-up work.

The PNG format permits 8-bit alpha for each indexed entry regardless of index bit depth, including repeated RGB entries. The implementation follows those rules and uses minimum legal index depths. [W3C PNG specification: palette and transparency](https://www.w3.org/TR/png-3/#11tRNS).
