# Large 1-bit pattern count investigation

Date: 2026-10-17. Baseline: `34a95d9`. **Decision: do not ship.** The candidate's counts were accurate, but native Android settings tests showed a repeatable CPU increase. Runtime source and behavior remain at the baseline.

## Final decision and scope

The parent and independent challenger rejected this candidate under the user's explicit requirement that it must not hurt performance. Warm physical Pixel 8 Pro Checker threshold changes repeatedly added approximately **1.3–1.6 ms scripting and 2.2–3.3 ms task time per committed change** across both paired runs. Input p95 increased about 0.5–1.2 ms. No added 50 ms stall or extra layout/style/paint cycle was observed, but the repeatable extra work still fails the confidence required by this task. A cheap isolated proof kernel does not establish a free whole-app update.

Native paired evidence is retained in `bench/large-pattern-challenge-2026-10-17/warm-ui-android-results.json` and `warm-ui-android-isolated-results.json` in the same directory. The independent challenge report records the full desktop/native protocol and limits.

The accuracy proof remains useful research. The archived candidate, patch, tests and results are retained in `bench/large-pattern-counts-2026-10-17/`; the parity and practical scripts explicitly import those archives rather than claiming to test shipped runtime. No new count setting, conversion behavior, rendering cache or automatic large-mask work ships. Large unproven pattern counts continue to require exact rendering evidence, which Preview can supply. A future attempt needs a new measured cause and acceptance gate, not a reinterpretation of these results as a performance pass.

## Problem and exactness rule

The wall deliberately redraws Checker, Bayer, Hatch, Noise and diffusion at its sampled dimensions. A color appearing in that sampled pattern need not occur at the corresponding full-source coordinate. Treating that sampled color as full-output evidence would report incorrect counts. The current safe fallback withholds large counts until an exact rendered mask supplies evidence.

Another full mask merely to display a caption is unnecessary for many inputs. Existing analysis already records a 256-bin histogram of brightness among pixels passing the analysis opacity cut. Its histogram remains per-frame when animation preparation unifies brightness ranges and Auto thresholds across frames.

## Proposed bounded proof

Reuse the exact tone lookup generated by the actual mask algorithm. For each occupied brightness bin in an ordered pattern:

- A tone at or below the smallest pattern cutoff proves the first role at every possible coordinate.
- A tone above the largest cutoff proves the second role at every possible coordinate.
- An intermediate tone allows either role; its actual role depends on the pixel's location.

Union the definite roles and the possible roles. Equal unions prove the exact role set without reading source pixels. Both extrema commonly prove both roles. Entirely dark/light sources and empty sources can prove one or zero roles. An ambiguous outcome stays unknown, rather than inventing a missing color. Actual color counts still exclude None and deduplicate equal RGB inks.

This is independent of source dimensions, pattern phase, scale and incomplete tiles: the bounds include every cutoff, including cutoffs unused by a narrow source. That can produce a conservative unknown but cannot falsely establish absence. Finite-value checks must handle invalid numerical evidence conservatively; JavaScript's `NaN > cutoff` behavior must not accidentally become a proof.

Diffusion is stateful. Its histogram cannot generally prove even endpoint membership, because preceding pixels propagate error. One narrow exception is a source whose every occupied brightness maps to exactly zero or one. Every error is then exactly zero, including across transparent holes and every supported diffusion kernel. Only that case admits a histogram proof; other diffusion remains unknown.

## Prototype evidence

Run `node bench/large-pattern-counts-2026-10-17/check.mjs`. Its frozen prototype copies the formulas for investigation only; production must share tone preparation with `mask` instead of maintaining a second quantizer.

The initial run compares 8,415 cases against actual full masks: 70 varied geometries including 1-pixel dimensions, uniform dark/light/middle and transparent pixels; all five styles; Auto and endpoint/manual thresholds; shading 0/1/50/100; scales 1–4; matrices 2/4/8; hatch directions and spacings; diffusion variants; and unified frames with disjoint brightnesses. It checks both lower- and upper-role claims, not just successful exact results. There were no incorrect claims. The ordinary cases yielded 7,211 exact proofs and 1,189 conservative unknowns; fifteen additional unified-frame checks passed.

On a generated 2048² source, ordered histogram proof took roughly 0.02–0.03 ms versus 50–55 ms for full mask creation in this warm Node run. General diffusion remained unknown, avoiding its roughly 93 ms mask. These are host observations, not mobile latency promises. Browser, phone, cancellation and export acceptance remain required before shipping.

## Challenge and scope

An independent reviewer agreed with the lower/upper proof and identified the need to guard nonfinite tone values. It also challenged diffusion, confirming that only the all-binary-tone case has zero error everywhere. This change must not alter any converted pixel, analysis threshold, animation timing, slider, setting or output format. It must not start a new large analysis, retain masks or scan pixels repeatedly. Bounded coordinate probes are a separate optional extension and are not necessary for this first minimal proposal.

## Rejected candidate implementation and regression evidence

The archived candidate's `patternRoleBounds` shares the unchanged tone-lookup expression with `mask` and obtains cutoff extremes from the same pattern tile construction. Large-count inspection consumes lower-role evidence and marks the result exact only when no possible distinct visible RGB remains unobserved. None and duplicate inks are interpreted through the existing mapping. Weak cached role evidence is marked exact only when the role bounds themselves agree, so changing inks cannot promote uncertain evidence to certainty. These changes were reverted from runtime after acceptance testing.

The existing 256K mask bound remains. Unsupported large structural masks, intermediate-tone diffusion, ambiguous ordered phases and mismatched large analyses remain unknown. No coordinate probe, large mask allocation, pixel loop, new worker or rendering-cache change was added.

The targeted regression run passed 115 tests across the actual mask suite, prior 1-bit usage suite and eight new direct proof tests. A separate retained baseline mask module compared **660 full/sample masks across all eleven styles byte for byte**, with no differences. The direct helper tests compare bounds against actual masks, avoiding the false confidence of testing only a collector that can fall back to a full mask.

`practical.mjs` independently decodes the existing 1024²/2048² licensed sprite sheets, six-frame effect GIF and 48-frame animation, then compares the count with actual full masks. All reported counts were exact. Large sheets report two colors for Checker/Bayer/Hatch/Noise without a mask; general Atkinson correctly remains unknown. Host inspection including posted-task scheduling was approximately 0.13–0.98 ms on the large sheets in that run. Small animations retain existing behavior and count the complete clip.

`parity.mjs` alternates warmed baseline/candidate tiny 14² mask timing. Most differences were around 1–3%; Noise measured +0.0035 ms in the first run and approximately +0.009 ms in the final archive-reproduction run. Such microbenchmarks are noisy, so browser and device acceptance must judge whole-app regressions rather than interpret every ratio as a user-visible change. Saved results distinguish prototype, byte parity and practical host inspection. Subsequent native repeated settings tests supplied the negative performance evidence leading to rejection. The adapted archive-only parity and practical scripts were rerun successfully after runtime restoration, retaining 660 byte-identical comparisons and all twenty practical fixture/style cases.

The independent challenger additionally checked 281,136 direct bounds, including 264,144 exact proofs; 576,000 frozen-baseline mask comparisons covering about 194 million pixels; and 100 real 769×513 cases with luminance access blocked to prove the metadata path reads no source pixels. Twelve unknown results remained appropriately unknown. None/equal-ink cache reuse followed by newly distinct inks was compared against actual output. These correctness successes do not override the native performance failure.
